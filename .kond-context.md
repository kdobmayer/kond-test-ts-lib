## Test Patterns

Existing tests use Jest. Each module has a corresponding `.test.ts` file.

Example test (`src/pipeline/index.test.ts`):
```typescript
describe('Pipeline', () => {
  it('chains transform and filter', () => {
    const result = createPipeline(data)
      .filter((r) => r.dept === 'eng')
      .transform((d) => d.map(r => ({ ...r, senior: (r.age as number) >= 30 })))
      .execute();

    expect(result.data).toHaveLength(2);
    expect(result.data[0].senior).toBe(true);
    expect(result.stepsExecuted).toBe(2);
  });
});
```

## Constraints and Gotchas

- **Strict TypeScript**: The project uses strict mode. Avoid `any`.
- **Immutability**: Transformers should return new arrays. Records should be shallow-copied or newly created.
- **Validation Severity**: Validation results have severity levels (`error`, `warning`, `info`). Only `error` level makes a result invalid by default.
- **XML OOM**: The XML parser (`src/parsers/xml.ts`) is non-streaming and loads everything into memory.
- **Duplicated Type Guards**: Type guards like `isString` are currently duplicated in `src/validators/index.ts` (known "rough edge").
- **Untested Pivot**: The `pivot` transformer in `src/transformers/index.ts` is currently untested.
